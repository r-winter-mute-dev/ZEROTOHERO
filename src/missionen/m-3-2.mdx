Dein ESP32 ist im Netz. Aber wie sagt er Discord oder Telegram, dass es geklingelt hat? Er schickt eine **Anfrage** an deren Server, in einer festen Form, die beide Seiten verstehen. Diese Form üben wir hier ohne Hardware. **Deine Mission: Bau Anfragen zusammen und lies, was der Server antwortet.**

## Theorie

<Karte nr={1} titel="Anfrage und Antwort">
Im Internet läuft fast alles nach demselben Muster: Ein Gerät schickt eine **Anfrage** (Request), der Server schickt eine **Antwort** (Response). Die Sprache dafür heißt **HTTP**. Eine **API** ist die Liste der Anfragen, die ein Server versteht, sozusagen seine Speisekarte. Discord und Telegram beschreiben ihre API in der Dokumentation.
</Karte>

<Merke>Gerät fragt, Server antwortet. Die API sagt, welche Fragen der Server versteht.</Merke>

<Karte nr={2} titel="Methode und Adresse">
Jede Anfrage beginnt mit einer **Methode** und einer **Adresse** (URL). Die Methode sagt, was du willst: **GET** holt etwas ab, **POST** schickt etwas hin, **DELETE** löscht etwas. Die Adresse sagt, wohin. Für deine Klingel reicht fast immer: **POST** an die Adresse, die dir Discord oder Telegram gibt.
</Karte>

<Merke>GET holt ab, POST schickt hin. Eine Klingel-Nachricht ist ein POST.</Merke>

<Karte nr={3} titel="Header und JSON">
Nach Methode und Adresse folgen **Header**: Zusatzangaben wie `Content-Type: application/json`. Der sagt dem Server, in welcher Form der Inhalt kommt. Der **Inhalt** (Body) ist bei Discord und Telegram **JSON**: Namen in Anführungszeichen, ein Doppelpunkt, dann der Wert. Zum Beispiel `{"content": "Es klingelt!"}`. Fehlt ein Anführungszeichen, versteht der Server nichts.
</Karte>

<Merke>JSON: geschweifte Klammern, "Name": "Wert". Dazu der Header Content-Type: application/json.</Merke>

<Quiz id="k3" titel="Kurzcheck: JSON" fragen={[

]} />

<Karte nr={4} titel="Statuscodes">
Jede Antwort beginnt mit einer dreistelligen Zahl, dem **Statuscode**. Die erste Ziffer verrät das Wichtigste: **2xx** heißt geklappt, zum Beispiel 200 OK oder 204 No Content („geklappt, aber ich schicke nichts zurück“). **4xx** heißt: Deine Anfrage stimmt nicht, etwa 400 (unverständlich), 401 (falsches Passwort) oder 404 (gibt es nicht). **5xx** heißt: Der Server hat ein Problem.
</Karte>

<Merke>2xx = geklappt. 4xx = dein Fehler. 5xx = Fehler beim Server.</Merke>

## Der Baukasten

Hier steckst du Anfragen zusammen und schickst sie an einen **nachgebauten** Discord-Webhook. Nichts davon verlässt deinen Browser. Links siehst du, was der ESP32 später genau so verschickt, rechts die Antwort.

<Hinweis titel="Probier auch DELETE">
Schick einmal ein DELETE an den richtigen Webhook und danach wieder eine Nachricht. Wer die vollständige Adresse kennt, kann deinen Webhook also löschen oder in deinem Namen schreiben. Genau deshalb behandelst du sie in Mission 3.4 wie ein Passwort.
</Hinweis>

<Hinweis titel="Vereinfacht">
Der Übungs-Server ist nachgebaut. Die Statuscodes und Fehlermeldungen orientieren sich an der Discord-Dokumentation, der echte Server liefert aber mehr Header und Details. Discord antwortet auf eine Nachricht je nach Einstellung mit 204 oder mit 200 und der gespeicherten Nachricht [Fachquelle: Discord-Entwicklerdokumentation, „Execute Webhook“]. Deine Klingel akzeptiert deshalb beides.
</Hinweis>
