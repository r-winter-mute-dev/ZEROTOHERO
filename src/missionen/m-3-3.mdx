In Mission 3.2 hast du gesehen: Wer deine Webhook-Adresse kennt, kann in deinem Namen schreiben. Schickt die Klingel sie unverschlüsselt durchs WLAN, kann sie jeder mitlesen, der im selben Netz ist. Darum sprechen Discord und Telegram nur **HTTPS**. **Deine Mission: Bau eine verschlüsselte Verbindung auf und prüf, ob der Server echt ist.**

## Theorie

<Karte nr={1} titel="Verschlüsseln und Ausweis zeigen">
**HTTPS** ist HTTP mit einer Schutzschicht namens **TLS**. Sie leistet zwei Dinge: Sie **verschlüsselt** alles, was hin- und hergeht, sodass Mitlesende nur Zeichensalat sehen. Und sie lässt den Server einen **Ausweis** zeigen, das **Zertifikat**. Damit prüft der ESP32, dass er wirklich mit discord.com spricht und nicht mit einem Betrüger dazwischen.
</Karte>

<Merke>HTTPS verschlüsselt und prüft den Ausweis des Servers. Beides zusammen macht die Verbindung sicher.</Merke>

<Karte nr={2} titel="Die Vertrauenskette">
Wer stellt den Ausweis aus? Eine **Zertifizierungsstelle**. Das Zertifikat von discord.com ist von einer Zwischenstelle unterschrieben, und die wiederum von einer **Wurzel** (Root). Dein Handy und dein Browser kennen weit über hundert solcher Wurzeln von Haus aus. Dem ESP32 musst du sie selbst mitgeben. Beim Verbindungsaufbau prüft der ESP32 drei Dinge:

1. **Kette:** Führen die Unterschriften lückenlos bis zu einer Wurzel, die er kennt?
2. **Name:** Steht im Zertifikat genau die Adresse, die er aufgerufen hat, also discord.com? Ein echtes Zertifikat für eine andere Seite zählt nicht.
3. **Zeitraum:** Ist das Zertifikat heute gültig? Dazu gleich mehr.

Nur wenn alle drei stimmen, gilt der Server als echt. Die Bibliothek WiFiClientSecure erledigt das für dich, sobald du ihr die Wurzeln gibst.
</Karte>

<Merke>Geprüft werden Kette bis zur Wurzel, Name und Zeitraum. Der ESP32 vertraut nur Wurzeln, die du ihm mitgibst.</Merke>

<Karte nr={3} titel="Ohne Uhrzeit kein Vertrauen">
Jedes Zertifikat gilt nur in einem bestimmten Zeitraum. Um das zu prüfen, braucht der ESP32 die richtige Uhrzeit. Er hat aber keine Uhr mit Batterie: Nach dem Einschalten glaubt er, es sei der 1. Januar 1970. Deshalb holt er sich die Zeit zuerst über das Internet, mit **NTP** (Network Time Protocol). Das dauert meist nur einen Moment.
</Karte>

<Merke>Erst die Uhrzeit holen (NTP), dann HTTPS. Sonst hält der ESP32 jedes Zertifikat für ungültig.</Merke>

<Karte nr={4} titel="Die Abkürzung, die du nicht nimmst">
In vielen Anleitungen steht `client.setInsecure()`. Damit verschlüsselt der ESP32 zwar, prüft aber den Ausweis nicht mehr. Jeder kann sich dann als Discord ausgeben und deinen Token abgreifen. Merke dir: **Verschlüsselt heißt nicht automatisch echt.** Eine verschlüsselte Verbindung zu einem Betrüger ist genauso verschlüsselt. Zum kurzen Ausprobieren mag `setInsecure()` gehen. In deiner Klingel hat es nichts zu suchen.
</Karte>

<Merke>setInsecure() schaltet die Ausweisprüfung ab. Nicht in der fertigen Klingel.</Merke>

## Die Wurzeln für deine Klingel

Die Datei **wurzeln.h** enthält neun Wurzelzertifikate aus dem Zertifikatsspeicher von Mozilla. Damit erreicht der ESP32 Telegram und Discord. Discord läuft über den Dienst Cloudflare, und der wechselt zwischen mehreren Zertifizierungsstellen. Deshalb sind mehrere Wurzeln drin, nicht nur eine. Am Anfang der Datei stehen Name, Ablaufdatum und Fingerabdruck jeder Wurzel. Die erste läuft 2035 ab.

```cpp
// 0 to Hero – Mission 3.3: Verschlüsselt
// Baut zwei HTTPS-Verbindungen auf und prüft dabei die Zertifikate.
// Kommt ein HTTP-Statuscode zurück (egal welcher), hat die Verschlüsselung geklappt.
// Eine negative Zahl heißt: Die Verbindung kam gar nicht zustande.
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <HTTPClient.h>
#include <time.h>
#include "wurzeln.h"

const char* WLAN_NAME = "DEIN_WLAN";
const char* WLAN_PASSWORT = "DEIN_PASSWORT";

// Zertifikate sind nur in einem bestimmten Zeitraum gültig.
// Deshalb braucht der ESP32 zuerst die richtige Uhrzeit aus dem Internet (NTP).
bool uhrzeitHolen() {
  configTime(0, 0, "pool.ntp.org", "time.google.com");
  Serial.print("Hole Uhrzeit");
  for (int i = 0; i < 40; i++) {
    if (time(nullptr) > 1700000000) {       // nach November 2023: Uhrzeit ist gesetzt
      time_t jetzt = time(nullptr);
      Serial.print("\nUhrzeit (UTC): ");
      Serial.print(ctime(&jetzt));
      return true;
    }
    Serial.print(".");
    delay(250);
  }
  Serial.println("\nKeine Uhrzeit bekommen.");
  return false;
}

int httpsAbrufen(const char* url) {
  WiFiClientSecure client;
  client.setCACert(WURZELN);     // nur Server akzeptieren, deren Kette bei einer dieser Wurzeln endet
  HTTPClient https;
  if (!https.begin(client, url)) return -100;
  int code = https.GET();
  Serial.print("GET ");
  Serial.print(url);
  Serial.print(" -> ");
  Serial.println(code);
  if (code < 0) {
    Serial.print("Fehler: ");
    Serial.println(https.errorToString(code));
  }
  https.end();
  return code;
}

void setup() {
  Serial.begin(115200);
  delay(500);
  WiFi.mode(WIFI_STA);
  WiFi.begin(WLAN_NAME, WLAN_PASSWORT);
  Serial.print("WLAN");
  while (WiFi.status() != WL_CONNECTED) { Serial.print("."); delay(250); }
  Serial.println(" verbunden");

  uhrzeitHolen();

  int discord = httpsAbrufen("https://discord.com/api/v10/gateway");
  int telegram = httpsAbrufen("https://api.telegram.org/bot123:ungueltig/getMe");

  if (discord > 0 && telegram > 0) {
    Serial.println("Beide Verbindungen verschlüsselt und geprüft.");
    Serial.printf("KW-CHECK:m-3-3:%012llX:%d:%d\n", (unsigned long long)ESP.getEfuseMac(), discord, telegram);
  } else {
    Serial.println("Mindestens eine Verbindung ist gescheitert. Siehe Fehlermeldung oben.");
  }
}

void loop() {}
```

## Was du sehen solltest

Bei Discord fragt das Programm eine öffentliche Adresse ab, die jeder abrufen darf. Dort sollte **200** zurückkommen. Bei Telegram schickt es absichtlich einen erfundenen Token. Dort kommt ein **4xx-Code** zurück, zum Beispiel 401 oder 404. Das ist hier ein gutes Zeichen: Der Server hat geantwortet, also hat die verschlüsselte Verbindung mit geprüftem Zertifikat geklappt. Abgelehnt wurde nur der falsche Token.

<Merke>Jede positive Zahl heißt: TLS hat geklappt. Eine negative Zahl heißt: Die Verbindung ist schon vorher gescheitert.</Merke>

<Hinweis titel="Negative Zahl?">
Steht dort `-1` und darüber eine Meldung mit `X509` oder `Certificate verification failed`, passt keine Wurzel. Prüfe, ob `wurzeln.h` im Sketch steckt und ob „Uhrzeit (UTC)“ ein heutiges Datum zeigt. Nutzt dein Router einen Filter, der HTTPS aufbricht (manche Firmen- und Schulnetze tun das), klappt es dort nicht. Dann probier es zu Hause.
</Hinweis>

<details>
<summary><strong>Vertiefung: Wie lange halten die Wurzeln?</strong></summary>

Wurzelzertifikate gelten viele Jahre. Die Zwischenstellen und die Zertifikate der Server wechseln dagegen alle paar Monate. Weil der ESP32 nur die Wurzel kennen muss, merkt er davon nichts. Kritisch wird es erst, wenn ein Dienst zu einer Zertifizierungsstelle wechselt, deren Wurzel nicht in `wurzeln.h` steht. Dann erzeugt man die Datei neu. Das Werkzeug dafür liegt im Repository unter `firmware/werkzeuge/wurzeln_erzeugen.py`.
</details>
