## Theorie

<Karte nr={1} titel="Derselbe Chip, anderes Board">
Auf dem ESP32-CAM sitzt derselbe ESP32-Chip wie auf deinem DevKit. Alles aus Akt 2 und 3 gilt weiter. Dazu kommen eine **Kamera** (OV2640), ein Steckplatz für eine microSD-Karte und eine helle **Blitz-LED**. Dafür fehlt etwas: Der ESP32-CAM hat **keinen USB-Anschluss**. Den liefert eine kleine Programmierplatine, die **ESP32-CAM-MB**, auf die du ihn aufsteckst.
</Karte>

<Merke>Gleicher Chip wie in Akt 2, aber mit Kamera. USB gibt es nur über die aufgesteckte Programmierplatine.</Merke>

<Karte nr={2} titel="Wenig freie Pins">
Die Kamera belegt viele Pins: 15 Stück für Bilddaten, Takt und Steuerung. Weitere Pins teilt sich der Chip mit der microSD-Karte. Frei bleiben nur wenige, und davon sind einige Boot-Pins (Boss 2). Zwei Pins sind fest verdrahtet: **GPIO 4** schaltet die Blitz-LED, **GPIO 33** die kleine rote LED auf der Rückseite. Die rote LED leuchtet bei **LOW**, also umgekehrt wie gewohnt.
</Karte>

<Merke>GPIO 4 = Blitz, GPIO 33 = rote LED (LOW heißt an). Die meisten anderen Pins gehören der Kamera.</Merke>

<Karte nr={3} titel="PSRAM: Platz für Bilder">
Ein Foto braucht viel Speicher, mehr als die 520 KB, die der ESP32 intern hat. Deshalb sitzt auf dem ESP32-CAM ein zusätzlicher Speicherchip, das **PSRAM**. Laut AI-Thinker sind es 4 MB [Fachquelle: AI-Thinker, Produktangaben]. Die Arduino IDE schaltet es nur ein, wenn du das richtige Board auswählst: **AI Thinker ESP32-CAM**. Mit „ESP32 Dev Module“ läuft das Programm, aber die Kamera hat keinen Platz.
</Karte>

<Merke>Board „AI Thinker ESP32-CAM“ wählen. Nur dann ist das PSRAM für die Bilder eingeschaltet.</Merke>

## Das erste Programm

```cpp
// 0 to Hero – Mission 4.1: Wechsel auf ESP32-CAM
// Board in der Arduino IDE: "AI Thinker ESP32-CAM".
// Lässt die kleine rote LED auf der Rückseite blinken und prüft, ob das PSRAM erkannt wird.

const int ROTE_LED = 33;   // rote LED neben dem Reset-Taster, umgekehrte Logik: LOW = an

void setup() {
  Serial.begin(115200);
  delay(500);
  pinMode(ROTE_LED, OUTPUT);
  Serial.println();
  Serial.print("Chip: ");
  Serial.println(ESP.getChipModel());
  Serial.printf("Flash-Speicher: %u KB\n", (unsigned)(ESP.getFlashChipSize() / 1024));
  if (psramFound()) {
    Serial.printf("PSRAM gefunden: %u KB\n", (unsigned)(ESP.getPsramSize() / 1024));
  } else {
    Serial.println("Kein PSRAM gefunden. Ist als Board \"AI Thinker ESP32-CAM\" gewählt?");
  }
}

void loop() {
  digitalWrite(ROTE_LED, LOW);    // an
  delay(300);
  digitalWrite(ROTE_LED, HIGH);   // aus
  delay(700);
  if (psramFound()) {
    Serial.printf("KW-CHECK:m-4-1:%012llX:%u\n", (unsigned long long)ESP.getEfuseMac(), (unsigned)ESP.getPsramSize());
  }
}
```

<Hinweis titel="Upload hängt bei „Connecting…“?">
Laut Händler schaltet die MB-Platine selbst in den Upload-Modus [Fachquelle: Produktseite Roboter-Bausatz]. Klappt es trotzdem nicht, drück kurz die **RST**-Taste auf dem ESP32-CAM, während „Connecting…“ erscheint, nicht die Taste auf der MB-Platine.
</Hinweis>

Öffne nach dem Hochladen den seriellen Monitor mit 115200 Baud. Dort sollte „PSRAM gefunden“ stehen, und auf der Rückseite blinkt die rote LED.
