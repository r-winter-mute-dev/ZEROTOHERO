Jetzt steuert dein Programm den Motor: vorwärts, rückwärts, bremsen und langsam. Dazwischen sitzt der Motortreiber DRV8833. Er enthält zwei H-Brücken, also genug für beide Räder. **Deine Mission: Schließ einen Motor über den DRV8833 an den ESP32 an und lass ihn ein Programm abfahren.**

## Warum ein Treiber?

<Karte titel="Der GPIO ist zu schwach" nr={1}>
Ein GPIO-Pin des ESP32 liefert nur wenige Milliampere. Dein Motor braucht im Leerlauf über hundert Milliampere und beim Anlaufen ein Vielfaches davon (Mission 1.2). Direkt am Pin würde der Motor nicht laufen, und der Pin könnte Schaden nehmen.
</Karte>

<Karte titel="Zwei Stromkreise" nr={2}>
Der Treiber trennt Signal und Leistung. Die Eingänge AIN1 und AIN2 brauchen kaum Strom und bekommen ihr Signal vom ESP32. Der Motorstrom kommt aus einer eigenen Quelle am Anschluss **VM** und fließt über die H-Brücke im Treiber zum Motor.
</Karte>

<Karte titel="Der Schlaf-Eingang" nr={3}>
Der DRV8833 hat einen Eingang nSLEEP. Das n heißt: aktiv bei LOW. Laut Datenblatt zieht ihn ein interner Widerstand auf LOW, der Treiber schläft also, solange niemand den Pin auf HIGH legt. Manche Module legen ihn schon auf der Platine auf HIGH, andere führen ihn als Pin heraus, oft beschriftet mit EEP, SLP oder STBY.
</Karte>

<Merke>Der ESP32 gibt nur das Signal. Der Motorstrom kommt über VM aus einer eigenen Quelle. nSLEEP muss HIGH sein.</Merke>

## Das Programm

Die Funktion `motor()` nimmt eine Zahl von −255 bis +255. Positiv heißt vorwärts, negativ rückwärts, die Größe ist der PWM-Wert. Der jeweils andere Eingang bleibt auf 0.

```cpp
const int AIN1 = 25;
const int AIN2 = 26;
const int SLEEP = 27;

void motor(int v) {
  v = constrain(v, -255, 255);
  if (v > 0) { ledcWrite(AIN1, v); ledcWrite(AIN2, 0); }
  else if (v < 0) { ledcWrite(AIN1, 0); ledcWrite(AIN2, -v); }
  else { ledcWrite(AIN1, 0); ledcWrite(AIN2, 0); }
}

void bremsen() {
  ledcWrite(AIN1, 255);
  ledcWrite(AIN2, 255);
}

void setup() {
  pinMode(SLEEP, OUTPUT);
  digitalWrite(SLEEP, HIGH);            // Treiber aufwecken
  delay(2);
  ledcAttach(AIN1, 20000, 8);           // 20 kHz, 8 Bit
  ledcAttach(AIN2, 20000, 8);
}
```

Das vollständige Programm mit Ablauf, Rampe und Gerätenachweis liegt im Repository unter `firmware/roboter-akt-1-motor/r-1-4-motor-am-esp32/`. Es fährt immer wieder dieselbe Runde: vorwärts, Freilauf, rückwärts, bremsen, dann eine langsame Rampe von 0 bis 255.

<Hinweis titel="Warum 20 kHz?">
Bei niedriger PWM-Frequenz hörst du den Motor pfeifen, weil die Spule im Takt mitschwingt. 20 kHz liegen über dem, was die meisten Menschen hören. Der ESP32 schafft diese Frequenz bei 8 Bit Auflösung problemlos.
</Hinweis>

## Hochladen und zusehen

Programm hochladen, seriellen Monitor auf 115200 Baud öffnen, dann den Batterieschalter EIN. Der Monitor zeigt jeden Schritt an, und der Motor sollte genau das tun. Nach einer Runde erscheint die Nachweis-Zeile.
