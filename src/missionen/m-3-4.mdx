Bald steht in deinem Programm ein Schlüssel zu deinem Chat. Und vielleicht willst du deinen Code später zeigen: in einem Forum, wenn etwas nicht klappt, oder auf GitHub. Dann darf der Schlüssel nicht mitreisen. **Deine Mission: Zieh die Zugangsdaten aus dem Programm in eine eigene Datei.**

## Theorie

<Karte nr={1} titel="Was alles ein Schlüssel ist">
Drei Dinge in deiner Klingel sind geheim: das **WLAN-Passwort**, die **Webhook-URL** von Discord und der **Bot-Token** von Telegram. URL und Token sehen harmlos aus, sind aber vollwertige Schlüssel. Wer sie hat, kann in deinem Namen schreiben, ohne sich anzumelden. In Mission 3.2 hast du gesehen, dass man mit der URL einen Webhook sogar löschen kann.
</Karte>

<Merke>Webhook-URL und Bot-Token sind Passwörter, auch wenn sie nicht so aussehen.</Merke>

<Karte nr={2} titel="Eine eigene Datei">
Die Lösung: Alle Geheimnisse kommen in eine Datei namens **secrets.h**. Das Programm holt sie mit `#include "secrets.h"` herein. Teilst du dein Programm, lässt du diese eine Datei weg. Die Arduino IDE zeigt jede `.h`-Datei im Sketch-Ordner als eigenen Tab an, du siehst also immer, dass sie da ist.
</Karte>

<Merke>Geheimnisse wohnen in secrets.h. Das Programm selbst enthält keine.</Merke>

<Karte nr={3} titel="Die .gitignore">
Auf GitHub lädt man meist ganze Ordner hoch, da rutscht eine Datei schnell mit. Die Datei **.gitignore** listet auf, was Git nie hochladen soll. In diesem Projekt steht dort schon `firmware/**/secrets.h`. Mit einer Vorlage namens `secrets.example.h` zeigst du anderen trotzdem, welche Angaben nötig sind, nur eben mit Platzhaltern.
</Karte>

<Merke>Die .gitignore hält secrets.h von GitHub fern. Teilen kannst du nur die Vorlage mit Platzhaltern.</Merke>

<Karte nr={4} titel="Wenn es doch passiert ist">
Ein Schlüssel ist ausgeplaudert, zum Beispiel weil secrets.h doch auf GitHub gelandet ist? Dann reicht Löschen nicht, denn Git merkt sich alte Versionen, und Bots durchsuchen GitHub gezielt nach Schlüsseln. Mach den Schlüssel **ungültig**: Bei Discord löschst du den Webhook und legst einen neuen an. Bei Telegram schickst du `/revoke` an @BotFather und bekommst einen neuen Token. Das WLAN-Passwort änderst du im Router.
</Karte>

<Merke>Ausgeplaudert? Schlüssel ungültig machen und neu erzeugen. Löschen allein reicht nicht.</Merke>

**secrets.h** (deine echten Daten, nie teilen):

```cpp
#pragma once

#define WLAN_NAME      "DEIN_WLAN"
#define WLAN_PASSWORT  "DEIN_PASSWORT"
```

**Das Programm** (kann man zeigen):

```cpp
// 0 to Hero – Mission 3.4: Geheimnisse
// WLAN-Name und Passwort stehen jetzt in secrets.h, nicht mehr im Programm.
// Fehlt secrets.h, bricht das Übersetzen mit einer Meldung ab. Das ist Absicht.
#include <WiFi.h>
#include <string.h>

#if __has_include("secrets.h")
#include "secrets.h"
#else
#error "secrets.h fehlt: Kopiere secrets.example.h, nenne die Kopie secrets.h und trag deine Daten ein."
#endif

void setup() {
  Serial.begin(115200);
  delay(500);

  if (strcmp(WLAN_NAME, "DEIN_WLAN") == 0) {
    Serial.println("In secrets.h steht noch der Platzhalter. Trag deinen WLAN-Namen ein.");
    return;
  }

  WiFi.mode(WIFI_STA);
  WiFi.begin(WLAN_NAME, WLAN_PASSWORT);
  Serial.print("Verbinde");
  unsigned long start = millis();
  while (WiFi.status() != WL_CONNECTED && millis() - start < 20000) { Serial.print("."); delay(250); }
  Serial.println();
  if (WiFi.status() == WL_CONNECTED) {
    Serial.println("Verbunden, und kein Passwort steht im Programm.");
  } else {
    Serial.println("Keine Verbindung. Stimmen die Daten in secrets.h?");
  }
}

void loop() {
  if (WiFi.status() == WL_CONNECTED) {
    Serial.printf("KW-CHECK:m-3-4:%012llX:secrets-ok\n", (unsigned long long)ESP.getEfuseMac());
  }
  delay(5000);
}
```

<Hinweis titel="Fehlermeldung „secrets.h fehlt“?">
Dann liegt die Datei nicht im selben Ordner wie das Programm, oder sie heißt anders, zum Beispiel `secrets.h.txt`. Der Tab muss genau `secrets.h` heißen.
</Hinweis>
